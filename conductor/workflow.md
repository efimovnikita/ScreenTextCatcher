# Project Workflow — ScreenTextCatcher

## Руководящие принципы

1. **План — единый источник правды:** Вся работа отслеживается и фиксируется в `plan.md`.
2. **Осознанный технологический стек:** Любые изменения в стеке документируются в `tech-stack.md` до их реализации.
3. **Разработка через тестирование (TDD):** Написание модульных тестов для бизнес-логики, сетевых вызовов, парсинга Mistral OCR и конфигурации до или параллельно с кодом.
4. **Высокое покрытие тестами:** Целевой уровень покрытия ключевых модулей >80%.
5. **Фокус на надежности и UX:** Минимальное потребление памяти, отсутствие записи скриншотов на диск, надежная обработка сетевых сбоев.
6. **Редкие атомарные коммиты:** Коммиты производятся после полного завершения всех фаз трека (фичи или багфикса). Сводка выполненной работы помещается прямо в тело коммита.

---

## Жизненный цикл задач (Task Workflow)

Все задачи выполняются в строгом порядке:

1. **Выбор задачи:** Выбрать следующую доступную задачу из `plan.md`.
2. **Отметка о начале:** Перед началом работы изменить статус задачи в `plan.md` с `[ ]` на `[~]`.
3. **Реализация и тестирование (TDD):**
   - Написание модульных тестов на ожидаемое поведение (`dotnet test`).
   - Реализация минимально необходимого кода.
   - Прогон тестов и подтверждение успешного прохождения (`Green Phase`).
4. **Проверка качества:**
   - Код соответствует стилю из `code_styleguides/csharp.md`.
   - Отсутствие предупреждений и ошибок компиляции (`dotnet build`).
   - Покрытие тестами целевых модулей >80%.
5. **Завершение задачи:**
   - Изменить статус задачи в `plan.md` с `[~]` на `[x]`.
   - Локальные изменения сохраняются в рабочей копии без немедленного коммита (коммит откладывается до завершения всех фаз трека).

---

## Протокол верификации завершения фазы (Phase Completion Verification)

После завершения всех задач текущей фазы:
1. **Автоматическое тестирование:** Запуск полного набора тестов: `dotnet test`.
2. **Ручная проверка (Manual Verification):** Предоставление пользователю пошагового сценария проверки функциональности (запуск приложения, тестирование хоткея, окна настроек или логов).
3. **Подтверждение пользователя:** Ожидание явного подтверждения ("Да" / "Принято").
4. Отметка фазы в `plan.md`.

---

## Фиксация результатов трека (Track Commit Protocol)

После успешного завершения всех фаз трека и финальной верификации:
1. **Формирование сводки:** Подготовка подробного отчета обо всех изменениях, реализованных функциях и затронутых компонентах.
2. **Создание коммита:**
   - Формат сообщения:
     ```text
     feat(track): <Краткое описание фичи/трека>

     Сводка изменений:
     - Реализован компонент X
     - Написаны тесты для Y (>80% coverage)
     - Обновлены конфигурация и документация
     ```
3. Сохранение сводки прямо в теле коммита (Commit Message Body).

## Команды разработки (.NET 9 C#)

### Сборка
```powershell
dotnet build ScreenTextCatcher.sln
```

### Запуск тестов
```powershell
dotnet test
```

### Запуск приложения
```powershell
dotnet run --project ScreenTextCatcher
```

---

## Критерии готовности (Definition of Done)
1. Весь функционал задачи реализован согласно `spec.md`.
2. Модульные тесты написаны и успешно проходят (`dotnet test`).
3. Покрытие тестами соответствует целевому показателю (>80%).
4. Код форматирован по правилам `csharp.md` и компилируется без ворнингов.
5. Изображения экрана обрабатываются исключительно в RAM.
6. Выполнена верификация и подтверждение пользователем.
